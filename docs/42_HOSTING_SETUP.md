# SyncVas hosting setup

The product has three existing runtimes. No backend migration is needed.

| Runtime | Host | Deployment input |
| --- | --- | --- |
| Website and Next.js routes | Vercel | Repository root, Next.js preset |
| Database, teacher auth, durable functions and jobs | Convex Cloud | `convex/` |
| Live classroom board and viewport relay | Render Free | Root `render.yaml`, `socket-server/Dockerfile` |

## Render free relay

Create a Render Blueprint from this repository. Keep the service root at the repository root: its Docker build needs the root lockfile and `shared/` protocol.

`render.yaml` explicitly selects `plan: free`, the existing Dockerfile, one instance, `/healthz`, and deploys only when GitHub CI checks pass. Its build filter limits relay deployments to backend, shared protocol, dependency, and hosting changes. Do not enable horizontal scaling or multiple regions: room state and writer leases live in process memory. Schedule redeployments outside active classes, and verify actual deployment overlap and reconnect behavior on the host.

1. Sign in to Render or connect the Render app.
2. Create a Blueprint from `peterish8/SyncVas`, branch `main`, using root `render.yaml`. Review that the service plan is Free before creating it.
3. The Blueprint configures:

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `PORT` | `4001` |
| `SOCKET_PORT` | `4001` |
| `SOCKET_INTERNAL_SECRET` | Generated by Render; copy securely to production Convex and Vercel |
| `ALLOWED_WEB_ORIGINS` | Current website preview origin; add the production origin when available |
| `RELAY_SINGLE_INSTANCE` | `1` |
| `RELAY_TRUST_PROXY` | `1` for the Render public proxy; verify client-address behavior on the hosted service |

Do not copy `ALLOW_DEV_TEACHER`, `ALLOW_PROOF_SOCKET`, or `NEXT_PUBLIC_ENABLE_LOCAL_TEACHER` to any production service.

4. Use the actual generated `https://...onrender.com` service URL. Do not guess it from the service name.
5. Verify `/healthz`, Socket.IO connection and reconnect behavior, CORS from the website origin, and the teacher plus two students flow.

Render Free sleeps after 15 minutes without incoming HTTP requests or WebSocket messages; waking typically takes about a minute. Sleeping or restarting clears the relay's in-memory room state, so the existing reconnect/snapshot recovery must be exercised. Each workspace has 750 free instance hours per calendar month, shared across free services. If exhausted, Render suspends its free web services until the next month. No paid plan is selected by this configuration.

## Convex production

Authenticate to the account that owns SyncVas before running `npx convex deploy`. If that account is inaccessible, explicitly select a project in the correct account instead of silently replacing the development database.

Configure production Convex with:

- `SOCKET_INTERNAL_SECRET`: identical to the relay secret.
- `SOCKET_SERVICE_INTERNAL_URL`: the relay's HTTPS URL.
- `SITE_URL`: the website's exact HTTPS origin.
- Google OAuth credentials and Convex Auth signing keys/JWKS required by the installed authentication setup.

The Google redirect URI is `https://<production-deployment>.convex.site/api/auth/callback/google`. Remove development teacher/proof flags from the production deployment. Keep development and production configuration separate.

## Vercel production

Set these in the Production environment once the backend services are available:

| Variable | Value |
| --- | --- |
| `NEXT_PUBLIC_CONVEX_URL` | Production Convex HTTPS cloud URL |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | Production Convex HTTPS site URL |
| `NEXT_PUBLIC_SOCKET_URL` | Hosted relay HTTPS URL |
| `NEXT_PUBLIC_APP_URL` | Canonical website HTTPS origin |
| `SOCKET_INTERNAL_SECRET` | Matching production relay secret, server-only |
| `ALLOWED_WEB_ORIGINS` | Include the canonical website origin |

Run `vercel deploy --prod --scope pratzys-projects` only with the real settings. Keep the existing production preflight enabled; do not insert a fake relay URL to pass it.

Complete the teacher plus two students flow in `docs/25_ACCEPTANCE_TESTS.md` before claiming live classrooms are ready.

## GitHub deployment connections

Keep the one repository and use `main` as the production source for both services:

- **Vercel:** the project is already connected to GitHub. Pushes trigger deployments. Configure the real Production environment before expecting `main` production builds to pass; pull-request previews use the separate Preview environment.
- **Render:** after signing in, create the Blueprint from `peterish8/SyncVas`. Its source branch is `main` and `autoDeployTrigger: checksPass` waits for GitHub CI before redeploying the relay. Keep the service plan Free.
- **GitHub Actions:** `.github/workflows/ci.yml` verifies lint, strict types, permission and protocol tests, and the website build on pushes to `main` and on pull requests. A second job builds the relay's Docker image and checks its production health endpoint using an isolated test secret.
- **Convex:** production backend deployment remains separate. Configure authenticated Convex deployment access or its Vercel integration before adding automated schema/function releases. Never reuse the development account's inaccessible project or invent a deploy key.

The Render connection and Convex production credentials are pending account access. The committed files prepare these deployments; they do not claim those external connections already exist.
