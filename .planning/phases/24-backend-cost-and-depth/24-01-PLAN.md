<objective>Stop reactive queries recomputing aggregates by collecting child tables, so a doubt submission no longer re-reads every participant of every class the teacher owns.</objective>

<context>
`doubts.submit` patches `participants.lastSeenAt`. That invalidates every query that
collects participants — including `buildTeacherDashboard`, which collects the
participants of up to 100 sessions. Estimated ~450,000 document reads per class from a
single open dashboard tab. Measurements and assumptions: `.planning/BACKEND-OPTIMIZATION-DECISIONS.md`.

Implements docs/21 "keep reactive queries narrow" and "indexed queries", which the
current code violates. No protocol change, no client behaviour change except the
`myStanding` removal in task 5.
</context>

<tasks>
1. Extend `convex/schema.ts`. Add `studentCount: v.optional(v.number())` to `sessions`;
   add `answerCount: v.optional(v.number())` and `correctCount: v.optional(v.number())`
   to `quizQuestions`; add index `by_session_participant: ["sessionId", "participantId"]`
   to `quizScores`. All three fields are optional so existing rows stay valid — treat
   `undefined` as `0` at every read site rather than requiring a migration to land first.

2. Maintain `sessions.studentCount` in `convex/participants.ts`. `joinByCode` increments
   it in the same transaction as the participant insert, and only on the insert branch —
   a rejoin patches `lastSeenAt` and must not double-count. Rewrite
   `participants.countForSession` to read the one session document instead of collecting
   participants; keep the return shape `{ connectedCount }` so
   `components/room/participant-count.tsx` needs no change beyond a comment.

3. Rewrite the session read paths in `convex/sessions.ts`. `getTeacherSession` and
   `buildTeacherDashboard` read `session.studentCount ?? 0` and drop their participant
   collects. `buildTeacherDashboard` becomes a single indexed `take(100)` with no
   `Promise.all` fan-out.

4. Write `convex/internal/backfillCounts.ts` — an `internalMutation` that walks sessions
   and quizQuestions in bounded batches and sets the counters from the current child
   rows. Idempotent, resumable by cursor, and safe to run against a live deployment.
   It is run once per environment after deploy; it is not scheduled.

5. Fix the quiz paths in `convex/quiz.ts`:
   - `teacherQuestions` reads `question.answerCount ?? 0` / `correctCount ?? 0` instead
     of collecting every answer per question. This is the N+1.
   - `submitAnswer` looks up the score row through the new `by_session_participant`
     index with `.unique()` instead of collecting the session's scores and finding one
     in JavaScript, and patches the question's `answerCount`/`correctCount` in the same
     transaction as the answer insert.
   - Delete `myStanding`. Replace it with `leaderboardForRoom(sessionId)` returning a
     student-safe projection (participantId, displayName, points, correctCount, rank —
     never `correctIndex` or any answer detail). The client finds its own row.
     Rationale: `myStanding` takes `participantId`, so every student produces a distinct
     query-and-args pair and Convex computes the whole leaderboard once per student per
     answer. Identical args across students share one computation.
   - Do **not** change `leaderboardForSession` itself. Collecting a session's score rows
     is correct for ranking and is bounded by `maxSocketsPerRoom = 400`.

6. Record the authorization posture for `leaderboardForRoom` in a comment: it is gated on
   the session existing and being live, not on participant membership, matching the
   existing `doubts.listOpen`. Names and scores on a leaderboard are public to the room
   by design; doubt anonymity is unaffected because the doubts queue still shows no name.

7. Keep the `@phase` header comments in each touched file accurate.
</tasks>
