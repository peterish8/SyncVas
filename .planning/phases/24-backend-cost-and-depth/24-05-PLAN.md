<objective>Resolve the teacher once behind one interface and delete the 29 dev-twin exports, so authorization has one implementation to audit and the production bundle carries no local-dev mutation.</objective>

<context>
29 of 104 Convex exports are `*AsLocalTeacher` / `getLocal*` copies that differ only in
which permission helper they call. 28% of the deployed surface is a copy, and the dev
mutations ship to production gated on an env var read inside the helper rather than on
the function being absent.

Run this last. It touches 29 functions across 9 Convex files plus every client call site,
and it regenerates `convex/_generated/api.d.ts`; it will conflict with anything else
in flight. It does not make 24-01 or 24-02 cheaper, because the expensive queries already
live in shared private helpers that both twins call.

This changes no authorization *rule*. Every check that runs today still runs. If any
behaviour would change, stop and report rather than adjusting the rule.
</context>

<tasks>
1. Write `convex/teacherContext.ts` with **two** entry points, not one:

   ```
   teacherForQuery(ctx: QueryCtx): Promise<Doc<"users"> | null>
   requireTeacherForMutation(ctx: MutationCtx): Promise<Doc<"users">>
   ```

   The asymmetry is required, not incidental: `requireLocalDevTeacher` upserts the dev
   teacher row and so needs a `MutationCtx`, while queries must stay read-only. Collapsing
   these into one function would either put a write in a query or break local-dev
   bootstrap. Record that in the module comment so it is not "simplified" later.

   Add `requireSessionOwner` / `requireSessionOwnerForQuery` on top of them, keeping the
   existing `ConvexError` codes (`UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`) byte-for-byte
   so `lib/user-facing-errors.ts` and the UI need no change.

2. Select the adapter in one place. `isLocalDevTeacherAllowed()` chooses between the
   Convex Auth adapter and the local-dev adapter inside `teacherContext.ts`. No feature
   file reads the env var, and no feature file imports `authBootstrap` directly.

3. Delete the 29 twins and point each surviving function at the new helpers. The full list
   is in `.planning/BACKEND-OPTIMIZATION-DECISIONS.md`; regenerate it with
   `grep -rn "^export const .*AsLocalTeacher\|^export const getLocal" convex/*.ts` before
   starting, in case 24-01 through 24-04 changed it.

   Two functions need care rather than deletion:
   - `sessions.getLocalTeacherDashboard` returns an empty dashboard when no dev teacher
     exists, where `getTeacherDashboard` throws. Preserve the empty-result behaviour for
     the local-dev adapter; do not make production return empty instead of throwing.
   - `quiz.setRoomModeAsLocalTeacher` inlines the `SESSION_NOT_LIVE` check that
     `setRoomModeForOwner` also performs. Keep exactly one copy.

4. Update the client call sites. The branch currently lives in the components — e.g.
   `app/teacher/dashboard/page.tsx` picks `localTeacherEnabled ? api.sessions.getLocalTeacherDashboard : api.sessions.getTeacherDashboard`.
   After this change the client calls one function and the server picks the adapter. Sweep
   for `AsLocalTeacher`, `getLocal`, and `localTeacherEnabled` across `components/` and
   `app/` and remove the branching. `lib/local-teacher.ts` and `lib/teacher-access.ts` keep
   only what still has a caller.

5. Keep `sessions.issueSocketToken`'s `asLocalTeacher` argument as it is. It is an action
   parameter on a single function, not a duplicated export, and it already gates on
   `isLocalDevTeacherAllowed()`. Out of scope.

6. Prove the dev adapter is absent from a production build. Extend
   `lib/production-env.ts` and `tests/production-env.test.ts` so a production
   configuration with `ALLOW_DEV_TEACHER` unset fails closed, and add an assertion that no
   exported Convex function name matches `/AsLocalTeacher|getLocal/`.

7. Keep the `@phase` headers accurate; several of these files describe which milestone owns
   them and what must not be added.
</tasks>
