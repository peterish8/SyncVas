<objective>Make duplicate detection an indexed read and stop paying a moderation provider for a question the intake module has already identified as a duplicate.</objective>

<context>
`doubts.submit` reads the 100 most recent doubts and scans them in JavaScript, then
schedules `triageDoubt` on every deterministic accept regardless of duplication. Two
costs: ~105 documents per submission, and one provider call per duplicate.

The 100-document window is also a correctness limit — in a busy room a duplicate older
than 100 submissions is missed, so the teacher queue shows the same question twice.

Implements AGENTS.md "avoid unindexed full-table scans in production paths" and the
docs/14 cost-protection rule that deterministic screening precedes any provider call.
</context>

<tasks>
1. Add index `by_session_normalized: ["sessionId", "normalizedText"]` to `doubts` in
   `convex/schema.ts`. No data migration is needed: `normalizedText` is a required field
   already written on every insert, and Convex builds the index over existing documents at
   deploy time.

2. Replace the `take(100)` duplicate scan in `convex/doubts.ts` `submit` with an indexed
   lookup on `[sessionId, normalizedText]`. Take the most recent non-rejected match rather
   than `.unique()` — the same normalized text legitimately appears more than once across
   a class, so uniqueness is not an invariant and `.unique()` would throw.

3. Carry the original's triage verdict onto the duplicate. When a duplicate is found and
   its status is already `accepted`, `uncertain` or `answered`, copy `status`,
   `reasonCode` and `relevanceScore` onto the new row and **do not** schedule
   `triageDoubt`. Schedule triage only when there is no duplicate, or when the duplicate
   is still in `screening`.

4. Keep the rate-limit read as it is. `by_participant_created` with
   `take(DOUBT_RATE_LIMIT_MAX)` is already indexed and bounded at 5 documents.

5. Confirm `deterministicScreen` still runs before any of the above, so a rejected doubt
   costs one screening call and no reads. Do not move it.

6. Keep the `@phase` header comments accurate.
</tasks>
