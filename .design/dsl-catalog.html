Board grammars for a CS classroom

Short text blocks that compile into real board content, so a teacher types six lines and the class sees a diagram, a themed code card, or a tensor pipeline — instead of watching a rectangle get drawn by hand.

18 grammars 3 build waves Scope: post-v1 Sept 2026

The architecture

Build one block, then only ever add compilers

Every item in this catalog is the same feature wearing a different grammar. The teacher opens a block panel, types a short source, and presses render. A registry looks up the grammar and calls a pure function:

// lib/blocks/registry.ts
type Compiler = (source: string, opts: BlockOpts) =>
  { elements: ExcalidrawElement[]; files?: BinaryFiles };

// The source survives on the element, so a block stays re-editable
// and re-themeable long after it is on the board.
element.customData = { sv: { lang: "code", source, opts } };

That one decision is what makes the rest cheap. Compiled output is ordinary Excalidraw content, so it rides the board:update event you already have, lands in the final snapshot you already persist, and exports through the path you already built. No new socket events. No Convex schema change. The teacher-only-writer rule is untouched.

Each new grammar is then a self-contained pure function with a unit test and no infrastructure work — which is the only way a solo dev ships eighteen of anything.

Why this beats an image

A compiled block is made of real shapes, so the teacher can circle a node, draw an arrow to it, or drag it apart mid-explanation. That is the entire difference between a whiteboard and a slide deck, and it is the reason to compile rather than paste a picture.

Cost model

Two compile targets

Which target a grammar hits is the single biggest driver of what it costs to build and what it costs to sync.

Target A · native shapes → convertToExcalidrawElements()

Boxes, arrows, ellipses and text laid out by your compiler and handed to Excalidraw's public skeleton API. Fully editable, annotatable, and a few KB of JSON.

Use for anything structural: graphs, trees, layer stacks, tables, state machines, plots.

Target B · image + source → SVG element + customData

For content needing real typographic fidelity — syntax colour, mathematical typesetting. Renders to an image element; the source stays in customData so it re-renders on a theme change.

Use for code cards and LaTeX only. Everything else should be Target A.

Blocker · fix before any Target B work

components/board/board-canvas.tsx:317 does void files; and publishScene in use-board-sync.ts sends only { elements, appState }. Binary files are never transmitted, so today an image-bearing element would render for the teacher and appear blank for every student. Your protocol already allows it — boardUpdateSchema has an optional files field capped at 2 MB — the client just never fills it.

Wire that first, and render blocks to SVG rather than PNG. A themed code card is a few KB as SVG and several hundred KB as a retina bitmap; the 2 MB cap is reached fast otherwise.

Wave 1

Near-free wins

Two of these are mostly integration work on libraries that already exist.
Target BEffort M /code

A themed code card — the thing you asked for. Shiki uses VS Code's own TextMate grammars, so the colours are literally the editor's.

/code python theme=one-dark title=quicksort.py focus=5-7
def quicksort(a):
    if len(a) <= 1: return a
    p = a[len(a) // 2]
    left  = [x for x in a if x < p]
    mid   = [x for x in a if x == p]
    return quicksort(left) + mid + quicksort(right)

Options line numbers, focus= to dim everything else, reveal= for progressive disclosure, diff mode for before/after. Themes six fixed: one-dark-pro, github-light, github-dark, nord, catppuccin-latte, monokai.

Target AEffort S /mermaid

Straight passthrough to @excalidraw/mermaid-to-excalidraw (MIT, actively maintained). The cheapest large capability on this page.

/mermaid
sequenceDiagram
  Client->>Server: SYN
  Server-->>Client: SYN-ACK
  Client->>Server: ACK

Native flowchart, sequence, class, ER, state. Image fallback gitgraph, gantt, mindmap, timeline, pie, quadrant, sankey, xychart. Covers control flow, protocols, OOP design, schemas and lifecycles in one grammar.

Target BEffort S /math

KaTeX. Non-negotiable for any ML course — every loss, gradient and attention definition is notation.

/math reveal=step
\text{Attention}(Q,K,V) =
  \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V

Key mode reveal=step on an align block shows one line of a derivation at a time. Backprop and probability proofs are exactly where students fall off, and where a full wall of algebra loses them.

Wave 2

The ones nobody else does live

These are the differentiators. All Target A, all pure layout functions.
Target AEffort L /tensor

A shape pipeline that computes the output shapes. Research on ML teaching keeps landing on the same thing: 4-D shape confusion is where students stall.

/tensor
x: (32, 3, 224, 224)   # N, C, H, W
conv2d 64 k=3 s=2 p=1  → (32, 64, 112, 112)
maxpool k=2            → (32, 64, 56, 56)
flatten                → (32, 200704)
linear 10              → (32, 10)

Why it wins the arrows are derived, not typed. A teacher changes the stride and the whole chain updates live — which answers "why did my dimensions break" better than any static slide.

Target AEffort M /ds

Data structures as shapes. Python Tutor's documented weakness is exactly this: it shows variable state well and trees or graphs badly.

/ds bst
50 -> 30, 70
30 -> 20, 40
70 -> 60, 80
mark path 50,70,60

/ds array [5,2,9,1,7] index highlight=1,3
/ds list 3 -> 7 -> 11 -> null
/ds graph directed weighted
A -> B : 4

Covers array, linked list, stack, queue, BST, heap, graph, hash table with buckets. The single highest-volume drawing in any DSA course.

Target AEffort M /calltree

Expands a recursion tree from a call. Repeated subcalls get tinted, so the case for memoisation makes itself visually.

/calltree fib(5) memo=off
# toggle memo=on and the duplicate
# subtrees collapse to cache hits

Why it wins recursion is taught by drawing this tree by hand every single term, badly, under time pressure.

Target AEffort M /dp · /trace

Filled tables with a declared fill order — dynamic programming grids and loop-execution traces.

/dp lcs "ABCBDAB" "BDCABA" fill=row
/trace cols=i,j,swap?
0,1,no
1,2,yes

Pairs with step reveal — walk the grid one cell at a time while talking, instead of pre-drawing a finished table nobody watched get built.

Target AEffort M /plot

Curves from a formula or a list. Complexity growth, activation shapes, loss curves, gradient descent on a contour.

/plot bigo n, n*log(n), n^2, 2^n  n=1..40
/plot fn sigmoid, relu, tanh  x=-6..6
/plot loss train=[...] val=[...] mark=overfit

Covers the two most-drawn graphs in the building: why O(n²) hurts, and what overfitting looks like.

Target AEffort M /nn · /attention

Layer stacks with parameter counts, and attention score grids. The existing tools here are LaTeX packages (PlotNeuralNet) or click-only web apps (NN-SVG) — neither works live on a board.

/nn
input 784
dense 128 relu   # 100,480 params
dropout 0.2
dense 10 softmax # 1,290 params

/attention seq=6 heads=8 dim=512 show=qk

Why it wins the parameter arithmetic is the lesson. Auto-computing it makes "where do 100k weights come from" a two-second answer.

Wave 3

Course-specific, add on demand

Each is small once the block primitive exists. Ship the ones your actual teachers ask for.
Target AEffort S /dfa · /nfa · /tm

Automata for theory of computation, including regex → NFA expansion.

/dfa
start q0 ; accept q2
q0 -a-> q1
q1 -b-> q2
q2 -a,b-> q2

Note double-circle accept states and self-loops are fiddly freehand and trivial to generate.

Target AEffort S /mem

Stack and heap with pointer arrows — the classic C/C++ box-and-arrow diagram.

/mem
stack: main → head*
heap: 0x1a{val:3, next:0x2b}
      0x2b{val:7, next:null}

Fills the gap Python Tutor leaves for anything pointer-heavy or non-Python.

Target AEffort S /bits

Labelled bit fields — two's complement, IEEE-754 layout, masks, packet headers.

/bits 0xC0A80101 width=32 group=8
/bits float32 -3.75 label=sign,exp,mantissa

For systems, architecture and networking courses.

Target AEffort S /confusion

Confusion matrix that derives precision, recall, F1 and accuracy from the four cells.

/confusion [[45,5],[8,42]] labels=spam,ham
# P .849  R .900  F1 .874  Acc .870

Why it wins students memorise the formulas and still can't place them on the grid. Showing both together fixes that.

Target AEffort S /truth · /kmap · /circuit

Digital logic: truth tables, Karnaugh maps with groupings, and gate diagrams from a boolean expression.

/circuit out = (a AND b) OR (NOT c)
/kmap f(a,b,c,d) = Σm(0,1,4,5,12,13)

For first-year digital design, where the drawing is most of the work.

Target AEffort S /sched · /matrix · /table

The remainder: CPU scheduling gantts and page tables for OS; matrix ops with dimension checking for linear algebra; plain comparison tables everywhere.

/sched rr quantum=4
P1 burst=10 ; P2 burst=5

/matrix A(3x4) @ B(4x2) check

Note /matrix ... check highlighting the matching inner dimensions is a one-hour build that prevents a term's worth of confusion.

Cross-cutting

Three mechanics worth more than any single grammar

Instructors interviewed about live coding describe the same failures. These three answer them directly, and each applies to every block on the page.

  • When I say we now make a loop, I have to write something completely different than what I'm saying.

    Step reveal. Author the whole block up front, disclose it in chunks. The teacher talks over a stable artefact instead of racing their own typing.

  • When the code gets complex, I tend to focus too much on the debugging and I lose the audience.

    Snippet library. Pre-authored blocks per class, inserted in one action. No typos, no dead air, no unplanned debugging detour.

  • The feeling of being observed by hundreds of students creates a psychological pressure.

    Live line pointer. The teacher taps a line and every student sees it highlight. It is an ephemeral event like your teacher viewport — no board version bump, no persistence, ~20 lines of protocol.

Fits an existing pattern

The line pointer is the same shape as teacher:viewport: volatile, lossy-safe, teacher-only, never touching boardVersion. You already have the validation, the room scoping and the writer check — it is one more entry in SOCKET_EVENTS.

Implementation notes

Details that will bite

Why code cards must be images, not text elements

Excalidraw ships FONT_FAMILY.Cascadia, so plain monochrome code could be a native text element in a proper monospace face. But a single text element carries one colour. Syntax highlighting would need one element per token, which explodes element count and makes the scene painful to select and move.

Render to SVG instead and keep the source in customData. You lose in-place text editing and gain correct colour, correct ligatures, and a scene that stays manageable. Re-opening the block panel gives editing back.

Shiki bundle size and the six-theme decision

Shiki's full bundle is 1.2 MB gzipped — unusable here. The fine-grained bundle, composing languages and themes individually, lands around 200 KB for a realistic set. That is the whole reason to fix the theme list at six rather than expose Shiki's full catalogue.

Pick languages the same way: Python, C, C++, Java, JavaScript, TypeScript, SQL, and a plain-text fallback covers essentially every CS course. Load them lazily on first block insert so the classroom's initial paint is unaffected.

Theme defaults, and a projector caveat

Default a code card to match the board theme — dark board, dark card — and let the teacher override per block. That is the behaviour people expect and it costs nothing.

Worth surfacing in the UI though: dark themes wash out badly on cheap classroom projectors, and instructors report tuning text size and syntax highlighting specifically for back-of-room legibility. github-light at a large size is the safest lecture-hall default even when the teacher's own board is dark.

Keeping compiled blocks out of the doubts and moderation path

Block sources are teacher-authored and go nowhere near the moderation adapter. Keep it that way — no block content in moderation requests, and no block source in telemetry, matching the rule already applied to doubt text.

Do bound the source: cap block source length and compiled element count per block, and reject a compile that would push the scene past the existing 900 KB envelope limit rather than emitting an oversized board:update the relay will drop.
